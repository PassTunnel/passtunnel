One-time codes

One-time codes, handled.

PassTunnel generates the code and sends it with your password. If 5 seconds or less are left in the code window, it waits for a fresh one, and it never sends the same code twice.

CLI & MCP

Security model

Your secrets stay on your Mac.

Creating a tunnel needs root. PassTunnel keeps that part small and signature-checked, and you approve it once.

What happens when you click Connect

PassTunnel.app, signed with Developer ID and notarized by Apple, talks over XPC to a small privileged helper that you approve once in System Settings and that accepts only the signed app. The helper runs only the signed openvpn or openfortivpn bundled inside the app, with sanitized OpenVPN configurations.

Login Keychain, no iCloud sync

Passwords and TOTP secrets stay in your login Keychain on this Mac. They do not sync to iCloud.

Only your VPN server

Nothing is sent anywhere except your VPN server. No sudoers rule and no admin password at every connect: you approve the helper once.

FAQ

Questions

Why does PassTunnel need a privileged helper?

Creating a tunnel interface and changing routes and DNS requires root. Instead of a sudoers rule or an admin password at every connect, PassTunnel uses a small helper that you approve once in System Settings. It only accepts the signed app and only runs the signed openvpn and openfortivpn bundled inside it, with sanitized OpenVPN configurations.

Where are my secrets stored?

In your login Keychain, with no iCloud sync. With Touch ID turned on for a profile, its secrets are encrypted with a Secure Enclave key.

Which VPN types does it support?

OpenVPN and FortiGate SSL VPN. Signed openvpn and openfortivpn are bundled, so there is nothing else to install, and you can connect several VPNs at once.

Does it work without TOTP?

Yes. Set the one-time code to “None” for a plain user name and password or a certificate-only VPN, or to “Ask each time” if you use a hardware token or SMS.
