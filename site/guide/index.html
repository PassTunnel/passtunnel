Install

PassTunnel needs macOS 13 Ventura or later on a Mac with Apple silicon. Cisco AnyConnect and Palo Alto GlobalProtect profiles need macOS 15.4 or later; on an older macOS the rest of the app works as usual.

Disk image

  1. Download the disk image and open it.
  2. Drag PassTunnel to Applications.
  3. Open PassTunnel from the Applications folder. The helper (next section) can only be installed from there.

The app is signed with a Developer ID and notarized by Apple. What changed in each version is in the release notes.

Homebrew

Homebrew commands 
$ brew trust passtunnel/tap
$ brew install --cask passtunnel/tap/passtunnel

Homebrew loads casks from third-party taps only after you trust the tap, hence the first line. The cask also links the passtunnel command (see Command line). To build the app yourself, follow Build from source in the README.

First launch

Without any profile, the window opens on Add your first VPN. The first thing to do there is to approve the helper.

Approve the helper

Creating a tunnel interface and changing routes and DNS requires administrator rights. Instead of asking for your admin password at every connect or adding a sudoers rule, PassTunnel installs a small helper that you approve once. The helper accepts requests only from the signed PassTunnel app and only runs the signed openvpn, openfortivpn and openconnect that ship inside it. The security model has the details.

  1. On the Add your first VPN screen, find the Install the helper card at the bottom and click Install Helper.
  2. Turn PassTunnel on in System Settings → General → Login Items. macOS asks once. While the approval is pending, the card offers Open Login Items….
  3. The card changes to “The helper is installed and running.” when it is done.

You can also do this later from Settings → Helper, which shows the helper’s status (Installed and running, Waiting for your approval, Not installed, Needs an update or Not responding) with buttons such as Install Helper, Update Helper, Repair Helper, Open Login Items… and Remove Helper…. After an app update, the helper is updated automatically as soon as no VPN connection is active, when PassTunnel runs from the Applications folder.

The card and Settings → Helper also offer Install and repair the helper automatically, off by default. With it on, a copy in the Applications folder installs the helper by itself on the first run and when you press Connect without it, then connects as soon as you turn PassTunnel on in Login Items (within 5 minutes; Cancel Connecting stops the wait). It also installs the helper again when it stops answering while no VPN is connected. macOS still asks for your approval, and a helper you removed or switched off in Login Items is not installed again on its own.

Add a profile

Click + at the bottom of the sidebar (the view is titled Add a VPN), or drop a file onto the window. The File menu has the same items. What you do depends on what you were given:

  • An OpenVPN file (.ovpn or .conf). Drop it on the dashed area or use Choose File… (File → Import .ovpn…). You see a review of what is in the file before anything is saved. Files it references, such as ca ca.crt, are embedded automatically.
  • A FortiGate gateway. Choose Enter details by hand, then FortiGate (File → New FortiGate Profile…). Enter the Gateway host and the port, and use Fetch Fingerprint to pin the gateway’s certificate (SHA-256).
  • A Cisco AnyConnect server (macOS 15.4 or later). Choose Enter details by hand, then Cisco AnyConnect (File → New Cisco AnyConnect Profile…). Paste the address your IT team gave you in Server, for example https://vpn.example.com/staff; PassTunnel fills in the host, port and user group from it. Group is the group the server offers at sign-in; leave it empty for the server’s default.
  • A Palo Alto GlobalProtect portal (experimental, macOS 15.4 or later). Choose Enter details by hand, then Palo Alto GlobalProtect (File → New Palo Alto GlobalProtect Profile (Experimental)…). Enter the portal’s address without a path, for example vpn.example.com. If the portal lists several gateways, the first connect stops at Choose a gateway, or you set Gateway in the profile. Skip the portal and sign in to the gateway directly signs in to one gateway; Server must then hold the gateway’s address.
  • An authenticator QR code. Choose Scan a QR code on screen (macOS 14 and later) or Use a QR image. PassTunnel asks what kind of VPN the code is for, then opens a new profile with the code filled in.
  • A .passtunnel file from a colleague. See Share profiles.

Then open the profile editor (Edit in the toolbar). In the first card, enter the User name (leave it empty to be asked each time) and the Password. Under Advanced → Sign-in, the password can also be asked each time, or not used (certificate-only OpenVPN). Secrets are written to the Keychain only when you press Save (Add Profile for a new profile).

Limits of Cisco AnyConnect and GlobalProtect

Both sign in with a user name, a password and, if the server asks for one, a one-time code. Neither supports sign-in through a web browser (SAML or single sign-on) or client certificates. Cisco AnyConnect also does not support host scan (Cisco Secure Desktop, HIP, TNCC) or RSA SecurID, and does not follow a server that sends you to another host after sign-in. For GlobalProtect, the host information report (HIP) is never sent: the connection goes on, and PassTunnel says access may be limited.

If the server’s certificate is signed by an authority your Mac trusts, there is nothing more to do. Otherwise, Fetch Fingerprint in the editor reads the server’s key and asks whether to trust it. Compare the fingerprint with the one your IT team published first. GlobalProtect has only been tested against openconnect’s own test server, so please tell us how it works for you.

Add the one-time code

In the profile editor, the One-time code card shows the live code with a countdown ring, so you can compare it with your authenticator app before saving. Use any of these:

  • Scan QR on screen (macOS 14 and later). A system picker asks which window or display shows the QR code, for example the authenticator setup page in your browser. The picture is read in memory and never saved. This needs no Screen Recording permission; only if the picker cannot start does PassTunnel offer to scan your screens instead, and macOS then asks for that permission.
  • Choose image… to pick a screenshot of the QR code, or drop the image onto the card or the window.
  • Paste secret: a Base32 or hex secret, an otpauth:// link, or a copied image.

An otpauth:// link also sets the digits, period and algorithm (SHA-1, SHA-256 or SHA-512). HOTP and otpauth-migration:// links are not accepted.

To type the secret by hand, or to change digits, period or algorithm, open Advanced and use One-time code there: Generate shows the Secret field, digits, period and algorithm.

The same setting has two other values. None is for a plain user name and password or a certificate-only VPN. Ask each time is for a hardware token or SMS: a small sheet asks for the code when you connect.

Choose how the code is sent

Servers disagree on how the code should arrive. Choose it per profile in the editor’s Code format menu. The editor’s Server receives shows the result with your user name and the live code; the password is always masked. With the password secret and the code 123456:

  • Append (the default): secret123456
  • Prepend: 123456secret
  • password:code: secret:123456
  • password,code: secret,123456
  • Custom template: any text around the placeholders {password} and {otp}; for example {password}#{otp} gives secret#123456. The template must contain {otp}; {password} is optional.
  • Sent separately: the password and the code travel as two values. For OpenVPN this is the static challenge (chosen automatically when the imported .ovpn contains static-challenge); for FortiGate it is the separate OTP field; for Cisco AnyConnect and GlobalProtect it is the answer to the server’s next prompt, after the password. It is the default for new profiles of every type except OpenVPN.

Wait for a fresh code

With Wait for a fresh code on (Settings → General → Connection, on by default), PassTunnel waits for the next code when 5 seconds or less are left in the current one, instead of racing the clock. A code that was already sent is never sent again, whatever the setting.

Connect and disconnect

Main window

  1. Select a profile in the sidebar.
  2. Click Connect. If the profile needs something that is not stored, such as a password set to Ask each time, a small sheet asks for just that, with the code already filled in.
  3. Click Disconnect when you are done. While connecting, the same button reads Cancel; after a failure it reads Try again.

The window shows the current code with a countdown ring and the next code, and, under What the server receives, what the sign-in sends. An activity list below it records what PassTunnel did.

Menu bar panel

The menu bar panel does the same from anywhere: a switch for each pinned or active profile (all profiles while none is pinned), with its live code, and items to copy the current code. Pin a profile with Pin to Menu Bar in its context menu.

Copy, hide and type codes

  • Click the code to copy it, or use the Copy code and Copy password + code buttons (Copy Code and Copy Password + Code in the ⋯ menu). The copy stays on this Mac and is cleared after 1 minute, or 30 seconds or 2 minutes as you choose in Settings → General → Clear copied code, unless you copied something else meanwhile.
  • Turn on Hide codes until clicked in Settings → General to show codes as bullets. A click shows them for 20 seconds. Copying never shows them, and the menu bar panel keeps hidden codes hidden.
  • Global shortcuts are off by default. Turn on Enable global shortcuts in Settings → Shortcuts to get ⌃⌥V, which connects or disconnects the default profile, and ⌃⌥C, which copies the current code. Turn on Type the code for me there and ⌃⌥C types the code into the focused field instead, which is for web portals that still ask for it. Typing needs Accessibility permission, which PassTunnel requests only when you turn the feature on.

Protect a profile with Touch ID

In the profile editor, turn on Require Touch ID before connecting (on a Mac without Touch ID it reads Require your Mac password before connecting). The switch appears for profiles that keep a secret in the Keychain.

  • The saved password and TOTP secret are then encrypted with a key in the Mac’s Secure Enclave, so a one-click connect needs you, not just your unlocked Mac.
  • Touch ID (or your Mac password) is asked before connecting and before showing, copying or typing codes. Disconnecting never asks.
  • Settings → General → Security → Ask again after (1, 5 or 15 minutes) sets how long one confirmation unlocks a profile.
  • Turning the switch off needs a successful Touch ID (or Mac password) confirmation when you press Save.
  • From the command line, passtunnel set ID require_auth=connect encrypts only the saved password, so connecting asks but live codes show without a prompt. If the profile has no saved password, the TOTP secret is encrypted instead and showing the code asks too.

Stay connected

Some of these are switches in the profile editor; the rest are settings or things PassTunnel does by itself.

  • Reconnect automatically if the link drops (editor switch). After a drop, PassTunnel reconnects with a fresh code, waiting 5, 15 and then 45 seconds between attempts. With it on, PassTunnel also reconnects right after the Mac wakes if the link dropped during sleep, unless the profile asks for Touch ID: then a notification says it disconnected while the Mac was asleep, and clicking it reconnects. The switch is unavailable when PassTunnel cannot connect without asking you (it needs a saved user name, the password in the Keychain and a generated code, or none); the editor says so. A rejected sign-in is never retried, so your account is not locked.
  • Health check (Advanced → Connection). Enter a host inside the VPN, such as 10.0.0.5 or host:port, and use Test to try it. While the profile is connected, PassTunnel checks it every 30 seconds. After two failures the profile shows as Connected · not responding and you get a notification; with automatic reconnect on, PassTunnel reconnects once per outage.
  • Session limit (Advanced → Connection), in minutes; 0 means no limit. PassTunnel reminds you before the server ends the session. How early is set in Settings → General → Notifications → Session limit.
  • Connect at login (editor switch). Profiles with this switch connect when PassTunnel opens at login. A profile that would ask for anything gets a notification to click instead.
  • Several VPNs at once. Each profile has its own status, log and settings. When you connect a profile whose routes or DNS names overlap with one that is connected, PassTunnel asks first: Cancel, Connect both or Switch to the new one. The shared traffic can go through only one of the two tunnels.

Share profiles

To share a profile, choose ⋯ → Share… (or run passtunnel export work -o work.passtunnel). The .passtunnel file holds the connection settings, appearance, code format and, for OpenVPN, the configuration file.

It never contains your password, your TOTP secret or your user name. A user name, password or proxy credentials embedded in the OpenVPN configuration are removed too. The embedded configuration can contain certificates and keys, so the file is written with 0600 permissions; share it the way you would share the .ovpn itself.

To import one, double-click it, open it from AirDrop or drop it on the window (File → Import Shared Profile… also works). Then add your own user name, password and TOTP secret in the editor.

Command line

Install the passtunnel command from Settings → General → Other → Command-line tool (Install…), or get it with the Homebrew cask. It does everything the app does. Profile IDs come from the profile name (Work becomes work).

$ passtunnel                          # status of all profiles
$ passtunnel connect work             # connect a profile
$ passtunnel code work -c             # print the live code and copy it
$ passtunnel status work --json       # exit code 3 when not connected
$ passtunnel disconnect --all
$ passtunnel import ~/Downloads/work.ovpn --name Work
$ passtunnel log work -f
$ passtunnel diagnose --check-clock

Every command with a result takes --json, and any command takes --no-input and --no-auth-prompt for scripts. Exit codes are stable. passtunnel help lists all commands. The README has more examples, and CLI-JSON.md describes every JSON object and exit code.

Use with AI assistants (MCP)

passtunnel mcp runs a Model Context Protocol server on standard input and output, so an AI assistant such as Claude Code, Claude Desktop, Cursor or VS Code can answer “is my VPN up?”, read the log of a failed connection and tell you what is wrong. Its tools are list_profiles, get_status, get_logs and diagnose.

  • Read-only by default. Only with --allow-connect can the assistant also connect and disconnect profiles.
  • A profile with Touch ID turned on still shows the prompt on your Mac, and nothing happens until you confirm.
  • No tool returns passwords, TOTP secrets, one-time codes or configuration files, and none creates, changes or deletes profiles.

Claude Code

Claude Code command 
$ claude mcp add passtunnel -- passtunnel mcp

This needs the passtunnel command on your PATH. Add --allow-connect after passtunnel mcp to let the assistant connect and disconnect.

Claude Desktop

Download PassTunnel-mcp-<version>.mcpb from the latest release and double-click it. Its setting Allow connect and disconnect is off by default. The bundle only launches the server built into the app, so PassTunnel must be installed in /Applications.

Other clients

Use the command /Applications/PassTunnel.app/Contents/MacOS/PassTunnel with the argument mcp, and add --allow-connect only if you want the assistant to connect. The server gets the same access as the passtunnel command; SECURITY.md explains what that means, including prompt injection.

Updates

PassTunnel keeps itself up to date. In Settings → Updates, Check for updates automatically is on by default and checks once a day; Check Now checks at once, and the app menu has Check for Updates…. An update is installed only when you click Install, and updates are signed and checked before they are installed. You can turn the daily check off in the same place.

With Homebrew, updates still arrive through the app, so brew upgrade leaves PassTunnel alone unless you run brew upgrade --greedy.

Troubleshooting

The helper is not approved

Connecting needs the helper. Open Settings → Helper to see its status. Waiting for your approval means PassTunnel still needs to be turned on in Login Items (Open Login Items…); Not installed needs Install Helper; Needs an update needs Update Helper; Not responding (macOS lists the helper as turned on, but it does not answer) needs Repair Helper. From a terminal, passtunnel helper status shows the same. The helper can only be installed when PassTunnel runs from the Applications folder.

Sign-in rejected

PassTunnel stops instead of retrying, so your account does not get locked. The failure card shows what it knows:

  • The code. Whether it was fresh or about to expire, and how many seconds were left when it was sent.
  • The clock. Codes are worked out from your Mac’s clock, and a clock that is off by 15 seconds or more makes every code wrong. Check the clock asks Apple’s time server how far off it is; the request carries nothing about you. A banner offers Open Date & Time. On the command line, use passtunnel diagnose --check-clock.
  • A changed password. “Changed your password at work?” with Update it in PassTunnel, when the password is in the Keychain.

If none of these fits, compare Server receives in the editor with what your server expects (see Choose how the code is sent).

Server unreachable or not found

If the server does not answer, your password and code were not sent. PassTunnel tries again every 30 seconds, up to 10 tries, and shows Try now, Stop and Copy details. Server not found points to the profile’s address.

Cisco AnyConnect and GlobalProtect messages

  • Server not trusted. The Mac does not trust the server’s certificate. Compare the fingerprint shown with the one your IT team published, then use Trust This Server…. For a GlobalProtect gateway, use Trust This Gateway….
  • Host scan required and Single sign-on required. PassTunnel does not support these (see Add a profile). Ask your IT team whether your account can sign in with a password and a code.
  • Requires macOS 15.4 or later. On an older macOS these types are shown with that note; their profiles can be shared and deleted but not connected.

An .ovpn file is rejected

The helper runs OpenVPN as root, so it refuses directives that would run scripts, load plugins or read and write arbitrary files. Lines whose effect PassTunnel takes care of itself are skipped, and you see them before the profile is added. The error lists every line that refuses the file; SECURITY.md has the complete lists.

Logs and diagnostics

  • ⋯ → Show Log opens the VPN tool’s log for a profile; Show all under the activity list opens a window of everything PassTunnel did. Passwords are never shown, and codes only by their first three digits.
  • passtunnel log work -f follows the log, and passtunnel log work --activity shows what PassTunnel did.
  • passtunnel diagnose reports the installation, the helper, the VPN tools and each profile’s problems.

Uninstall

  1. Disconnect all profiles.
  2. Remove the helper before deleting the app: Settings → Helper → Remove Helper…, or passtunnel helper uninstall.
  3. Turn off launch at login: Settings → General → Open at login, in the menu bar. Check that nothing is left under System Settings → General → Login Items.
  4. Quit PassTunnel and move PassTunnel.app to the Trash.
  5. Delete your data with these commands. The first removes profiles, configurations, logs and preferences; the second removes the open-at-login question; the third removes the command-line symlink, if you installed it. 
    $ rm -rf ~/Library/Application\ Support/PassTunnel
$ defaults delete com.furkanprlk.passtunnel 2>/dev/null
$ rm -f /usr/local/bin/passtunnel ~/.local/bin/passtunnel
  6. Delete the Keychain items: open Keychain Access and search for PassTunnel. Deleting a profile inside the app also removes its Keychain items.

With Homebrew, brew uninstall --zap --cask passtunnel also deletes your data and the Keychain items (the last two steps). A plain brew uninstall --cask passtunnel keeps both.
